# 나에게 맞는 안산 프로그램 찾기

설문 28문항(기본정보 3, 5점 척도 24, 걸림돌 1) → 지금 먼저 살펴볼 유형 하나 → 그 유형에서 지금 문의할 수 있는 곳 안내(물어볼 문장 · 전화 · 신청 방법).
결과 화면에서 원하는 점을 직접 적으면, 그 사람에게만 AI가 정보표 안에서 관련 있는 곳을 골라 이유와 함께 덧붙인다.

- 유형은 AI가 정하지 않는다. 척도 문항 점수로 정한다(아래 '유형을 정하는 규칙').
- 성격이나 건강을 진단하는 검사가 아니다. 유형마다 문항이 2개뿐인 추천용 초안이고, 신뢰도·타당도는 검증하지 않았다.
- 기본 결과는 AI 없이 프로그램 정보표에서 걸러서 만든다. AI가 실패해도 기본 결과는 그대로 나온다.
- 프로그램 정보표는 공식 출처에서 확인한 내용이다. 행마다 `확인날짜`와 `출처URL`이 있다.

## 실행

프로젝트 루트(이 폴더의 위 폴더)에서 실행한다.

```
.venv\Scripts\python -m pip install -r app\requirements.txt
.venv\Scripts\python -m streamlit run app\main.py
```

- PC: http://localhost:8501
- 휴대폰: PC와 같은 와이파이에 연결한 뒤, 실행 창에 나오는 Network URL로 접속한다.
- 테스트: `.venv\Scripts\python -m pytest app\tests` (실제 AI는 부르지 않는다)

## 유형을 정하는 규칙

전달 자료 '안산노믹스_24문항_설문과분류규칙'(2026-11-17)을 따른다. 코드는 `core/scoring.py`, 기준 점수는 `data/settings.yaml`의 `scoring`이다.

- 같은 유형의 두 문항을 더한다(2~10점). 유형끼리 점수를 빼지 않고, 역채점과 가중치는 없다.
- 기본정보(성별·태어난 해·일 여부)와 걸림돌은 점수에 넣지 않는다. 기본정보는 유형을 바꾸지 않고, 정보표의 대상 조건(`대상성별`·`최소나이`·`최대나이`·`대상재직상태`)과 견주어 안 맞는 곳을 빼는 데만 쓴다(11/22). 그 자리에서 견주기만 하고 저장하지 않으며 AI로 보내지 않는다.
- 설문 문항은 모두 답해야 넘어간다(넘어가기 단추가 없다). 채점 함수는 답이 빠져 있으면 0점이나 3점으로 채우지 않고 오류로 멈춘다.

| 답 | 결과 화면 |
|---|---|
| 점수가 가장 높은 유형이 하나 | 점수가 낮아도 그 유형을 대표 유형으로 보여준다 |
| 점수가 가장 높은 유형이 여럿(동점) | 무엇부터 볼지 본인이 고른다. 하나를 골라야 결과로 넘어간다 |

- 11/25에 바꿨다. 그전에는 7점이면 본인 확인을 받고, 모두 6점 이하면 유형을 주지 않았다. 지금은 유형이 없는 결과가 없다.
- 그래서 전부 '아니에요'라고 답한 사람도 유형을 받는다(12개 동점이라 본인이 고른다). 발표에 한계로 적는다.

- 대표 외에 8점 이상인 유형이 하나면 "이 분야도 함께 살펴보세요" 단추로 권한다. 여럿이면 '다른 분야도 보기' 안에 묶어 둔다.
- 대표가 정해져도 다른 유형을 본인이 눌러서 열 수 있다. 점수는 화면에 보여주지 않는다.

### 결과 화면과 그 밖의 화면 (11/22)

- 화면 순서(11/25): 설문 → (동점이면 고르기) → 조금 더 맞춰 보기(세부 질문 + 직접 적기 AI, 건너뛸 수 있음) → 결과. 결과 화면은 유형 카드 → '내 특징 자세히 보기' → 첫걸음 지도(핀 3곳 + '다른 곳 n곳') → 내 결과 저장하기·친구에게 공유하기 → 더 보기(함께 볼 유형, 다른 분야, 함께 찾아 주는 창구, 답변 확인·수정, 바라는 점 다시 적기) → 처음부터 다시 하기다. 핀을 누르면 그 곳의 안내 화면으로 가고, 위의 화살표나 아래 '결과로 돌아가기'로 돌아온다.
  - 지도에 놓는 곳은 대표 유형의 문의할 곳 → 둘러볼 목록 순서이고, AI가 고른 곳이 있으면 맨 앞에 별과 함께 놓는다. 핀 안의 그림은 `programs.csv`의 `핀그림` 칸을 따른다(건강 / 상담 / 일 / 가게 / 배움 / 문화 / 운동 / 모임 / 봉사 / 돌봄 / 돈 / 혜택 / 전화 / 온라인 중 하나. 비우면 기본 그림).
  - 맨 위 띠의 '처음으로'와 '처음부터 다시 하기'는 답이 지워진다고 한 번 되묻는다. 설문 중에는 '처음으로'가 없다.
- 유형마다 먼저 보여 주는 곳은 `settings.yaml`의 `top_n`(1곳)이고, 나머지는 '더 보기'로 연다. AI가 더 찾아 주는 개수는 `ai_top_n`(3곳)으로 따로 둔다.
- 세부 질문에서 주제를 고르면, `match_tags: true`인 유형(취미·배움·마음·혜택·돌봄·건강)은 그 주제의 `세부태그`가 붙은 곳만 남긴다. 맞는 곳이 하나도 없으면 빼지 않고 그 유형의 곳을 그대로 보여 주며 `widened_note`로 알린다. 돌봄은 `require_choice: true`라 누구의 돌봄인지 먼저 골라야 곳이 나온다.
- '설문 답변 확인·수정': 결과 화면 아래 접힌 칸에서 문항 하나를 누르면 그 문항만 다시 묻고 결과로 돌아온다. 결과는 답에서 다시 판정한다.
- '질문 없이 먼저 둘러보기': 첫 화면의 둘째 단추. 설문 없이 12개 분야를 열어 본다. 기본정보 답이 없으므로 대상 조건으로 거르지 않고, 응답 기록을 남기지 않고, 직접 적기(AI)도 두지 않는다. 실험에서는 '시작하기'(검사 경로)만 쓴다.
- 이 판정 규칙은 시범 운영 규칙이다. 검증된 기준이 아니므로, 실제 답과 결과 납득 여부를 보고 고친다.

## AI 추가 추천 켜기

지금은 구글 Gemini API의 무료 구간을 쓴다(`data/settings.yaml`의 `llm.provider: gemini`).
키는 https://aistudio.google.com/apikey 에서 발급받는다.

- PC에서 실행할 때: `.streamlit/secrets.toml` 파일을 만들고 아래 한 줄을 넣는다. 이 파일은 git에 올라가지 않는다.
- 배포된 앱: Streamlit Cloud의 앱 Settings → Secrets에 같은 한 줄을 넣는다.

```
GEMINI_API_KEY = "여기에 키"
```

키가 없거나 AI가 답하지 못하면 "지금은 맞춤 찾기가 되지 않아요" 안내만 나오고, 아래쪽의 기본 결과는 그대로다.
`settings.yaml`의 `show_error_kind: true`는 실패 원인의 종류를 화면에 작게 보여주는 점검용 설정이다. 실험 전에 `false`로 바꾼다.

"ㅇ", "없어"처럼 원하는 점이 없는 글에는 AI를 부르지 않고 "조금만 더 적어 주세요"라고 안내한다(`core/llm_matcher.py`의 `has_wish()`). 글자가 되지 않는 것은 자동으로 걸러지고, '없다는 뜻의 말'은 `settings.yaml`의 `free_empty_words` 목록에서 더하거나 뺀다. 목록에 없는 글("아무거나요")은 AI 지시문(`prompts/matching.md`)이 아무것도 고르지 않도록 막는다.

무료 구간에서는 보낸 내용을 구글이 서비스 개선에 쓸 수 있다. 그래서 시작 화면과 글 상자 위 안내에 "외부 AI 서비스(구글)로 보낸다"고 적었고, 주민번호·전화번호·이메일 형태는 보내기 전에 지운다(이름과 주소는 지우지 못한다). 실험 전에 무료 구간의 현재 약관을 확인하고, 참여 동의서에도 한 줄을 넣는다. `llm.provider`를 바꾸면 `settings.yaml`의 `free_privacy` 문구도 함께 고친다.
Claude로 바꾸려면 `llm.provider: anthropic`, `llm.model: claude-opus-5-5`로 고치고 `ANTHROPIC_API_KEY`를 넣는다.

### AI가 하는 일과 하지 않는 일

1. 사용자가 글을 적고 "적은 내용으로 찾아보기"를 누를 때만 한 번 부른다. 적지 않으면 부르지 않는다.
2. AI에게는 코드가 걸러 준 후보만 보낸다. 대표 유형과 본인이 연 유형의 '문의할 곳'이고, 대표 유형이 없고 연 유형도 없으면 지금 보여줘도 되는 곳 전체다. 성별·나이·일 여부는 보내지 않는다. 후보는 세부 주제로 좁히지 않는다(글에 다른 주제를 적어도 같은 유형 안에서는 찾을 수 있게). 글과 함께 살펴보는 유형 이름, 고른 세부 선택, 걸림돌이 가는데, 마음·건강처럼 `log_answer: false`인 세부 질문의 선택은 보내지 않는다.
3. AI가 고른 id는 후보와 다시 대조한다. 후보에 없는 것(지어낸 것, 끝난 것)은 화면에 나오지 않는다. AI가 쓴 이유 글은 200자에서 자른다.
4. 결과 상태는 세 가지다. `ok` 글에 맞는 곳을 찾음 / `partial` 일부나 전부를 찾지 못함(일반 창구로 잇는다) / `fail` AI 호출 실패.

### 정답표로 확인하기

지시문, 모델, 프로그램 정보표를 바꾸면 가상 사례(`tests/matching_cases.yaml`)로 다시 확인한다.

```
.venv\Scripts\python app\tests\eval_matching.py --check     # AI를 부르지 않고 정답표가 정보표와 맞는지만 확인
.venv\Scripts\python app\tests\eval_matching.py             # 실제 AI로 정확도와 시간 측정 (사례 사이 12초 쉼)
```

## 내용을 고치는 법 (코드 수정 없음)

파일을 저장하고 브라우저를 새로고침하면 반영된다. 형식이 틀리면 화면에 어느 파일 어디가 틀렸는지 나온다.
각 파일 맨 위 주석에 칸의 뜻이 적혀 있다.

| 고치고 싶은 것 | 파일 |
|---|---|
| 질문 문구, 척도 선택지 문구, 걸림돌별 안내 | `data/questions.yaml` |
| 유형 이름·문장, 유형별 세부 질문 | `data/types.yaml` |
| 프로그램·센터 정보 | `data/programs.csv` (엑셀로 열고 'CSV UTF-8'로 저장) |
| 화면 문구, 대표 유형 기준 점수, 유형마다 먼저 보여줄 곳의 수, 기록 켜기, AI 모델 | `data/settings.yaml` |
| AI에게 주는 지시문 | `prompts/matching.md` (`{type_name}` 같은 자리표시자 6개는 지우지 않는다) |

바꾸면 안 되는 것:

- 문항 id `Q_BARRIER`, `Q_PRIORITY`, `Q_FREE`와 유형 id `T01`~`T12`. 코드와 정보표가 쓴다.
- 척도 문항(`selection: scale`)은 유형마다 정확히 2개여야 한다. 문항의 `type`에 유형 번호를 적어 연결한다. 더하거나 빼면 앱이 켜질 때 어느 유형이 몇 개인지 알려 준다.
- 척도 선택지(`scale`)의 `value`는 1~5를 한 번씩 쓴다. `label`만 고친다.
- 기본정보 문항 id(`P_GENDER`, `P_AGE`, `P_WORK`)는 코드가 후보 거르기에 쓴다. 바꾸거나 지우면 앱이 켜질 때 알려 준다. 성별·일 여부의 선택지 id(`male`/`female`, `employed`/`self_employed`/`not_working`)는 정보표의 대상 조건 칸에 그대로 적는 값이라 바꾸지 않는다.
- 유형의 세부 질문(`types.yaml`의 `detail`)에 적을 수 있는 표시: `match_tags`(고른 주제에 맞는 곳만 남김), `require_choice`(먼저 골라야 곳이 나옴), `log_answer: false`(고른 선택지를 기록에도 AI에도 남기지 않음. 마음·건강), `prominent`(접지 않고 보여 줌), `enabled: false`(묻지 않음).
- 척도 문항 사이에 다른 문항을 넣지 않는다. 다른 문항은 척도 문항들의 앞이나 뒤에 둔다.
- 화면 색(연녹색 바탕, 청록 글자, 노란 주요 단추)은 `ui/style.py` 맨 위 `:root`의 색 값 한 곳에서 고친다. 노란색은 주요 단추(시작, 공식 안내 보기, 다음)의 바탕 칠로만 쓴다. 고른 답은 물빛 바탕과 청록 테두리로 구분한다.
- 결과 화면의 대표 유형 상자 맨 위에는 캐릭터 그림이 나온다. 그림은 `ui/assets/type-characters/`에 있고, 파일 이름은 `t01-female.webp`처럼 `유형 id(소문자)-성별.webp`다(유형 12개 × 여성·남성 = 24장). 설문에서 답한 성별의 그림을 띄우며, 성별은 그림을 고르는 데만 쓰고 저장하지 않는다. 그림을 바꾸려면 같은 이름의 파일로 덮어쓴다. 파일이 없는 유형은 그림 없이 나온다. 본인이 눌러서 연 다른 유형과 '질문 없이 둘러보기'에는 그림이 없다. 그림 설명(화면 읽기 도구용)은 `type_image_alt`에서 고친다.
- 시작 화면의 배치는 `ui/home.css`다. 그림 상자에는 유형 캐릭터 세 명이 선다(`ui/components.py`의 `HOME_CHARACTERS`, 그림 파일은 `ui/assets/type-characters/`). 노란 바탕·바닥·해는 `home.css`가 그린다. 꾸밈 그림이라 설명 글(alt)은 없다. 큰 제목은 `start_heading`, 팀 이름은 `team_name`, 팀 이름 옆 작은 글은 `start_audience`에서 고친다.
- 화면 맨 위 띠의 이름은 `top_title`(ANTI), 그 아래 작은 풀이는 `top_sub`다. 시작 화면 맨 아래의 작은 유의사항은 `start_privacy`·`start_ai_note`·`start_refresh`·`disclaimer`이고, 실제로 저장·전송하는 것과 같게 적어야 한다.
- 설문 위의 진행 표시(`progress_scale`)는 기본정보부터 걸림돌까지 한 줄로 센다('질문 4 / 28').
- 기관 카드는 이름·기관 → 공식 안내(노랑)·신청 단추 → '이렇게 물어보세요' → 전화 단추 → 장소·처음 이용할 때·대상·시간·비용 → 접힌 '물어볼 준비' 순서다. 물어볼 문장은 전화 단추 바로 위에 둔다. `장소`가 `전화 상담`처럼 찾아가지 않는 곳이면 '혼자 가도 되나요' 같은 방문용 질문은 붙이지 않는다(`ui/components.py`의 `REMOTE_PLACES`).
- 유형의 특징 글은 `data/types.yaml`의 `feature`다. 대표 유형 아래 '이 유형의 특징'과 결과 사진에 같은 글이 나온다. 그 유형의 문항 두 개와 `definition`을 풀어 쓴 2~3문장이고 160자까지다. "~라고 답하셨어요"처럼 답을 단정하지 않는다(두 문항 중 하나만 높아도 대표 유형이 된다). 화면 위치("아래에서")나 다른 유형 이름도 쓰지 않는다.
- '내 결과 저장하기'는 결과를 사진 한 장(세로 1080×1350 PNG)으로 만들어 보여 준다. '사진 저장하기'로 내려받거나 '카카오톡·메시지로 보내기'로 휴대폰 공유 창에 넘긴다. 보내기가 안 되는 브라우저에서는 사진을 길게 눌러 저장한다.
  - 사진에 들어가는 것: 앱 이름, 캐릭터 그림, 유형 이름·설명·특징, 곳 이름(프로그램명·기관명) 최대 3곳, 저장한 날. 답·점수·전화번호·걸림돌·직접 적은 글은 들어가지 않는다.
  - 곳은 대표 유형의 문의할 곳 → 둘러볼 목록 → 함께 찾아 주는 창구 순서로 처음 있는 것의 앞 3개다. 대표 유형이 없으면 창구 이름만 들어간다.
  - 사진은 `ui/result_image.py`가 그린다. 글꼴은 `ui/assets/fonts/`의 Pretendard(OFL 라이선스, 같은 폴더에 라이선스 글)다. 서버에는 한글 글꼴이 없으므로 이 폴더를 지우면 사진의 글자가 깨진다. 사진은 앱에 저장하지 않는다.
- 결과 화면 맨 아래 '친구에게 공유하기'는 `share_message`와 앱 주소만 보낸다. 답과 결과는 보내지 않는다. 휴대폰 공유 창을 띄우고, 띄우지 못하면 주소를 복사한다. 주소를 정해서 보내려면 `share_url`에 적는다(비우면 지금 열려 있는 주소).
- `settings.yaml`의 `text` 문구는 글만 고치고 줄을 지우지 않는다. `{count}` 같은 중괄호 낱말도 그대로 둔다. 지우거나 잘못 적으면 앱이 켜질 때 알려 준다.

### 프로그램 정보표(programs.csv)에서 꼭 알아둘 열

- `매칭가능`이 `Y`이고, `55~64세참여`가 `불가`가 아니고, `표시종료일`이 지나지 않은 행만 화면과 AI에 나간다. `종료시각`(한국 시각, 예: `14:00`)을 적으면 종료일 당일 그 시각부터 빠진다. 시각을 모르면 비워 두고, `표시종료일` 없이 `종료시각`만 적을 수는 없다. 그날 끝까지 보여주려면 비워 둔다(`00:00`을 적으면 종료일 0시부터 빠진다). 끝난 프로그램은 지우지 말고 `N`으로 둔다. `Y`면 `출처URL`이 있어야 한다.
- `유형태그`: 이 프로그램을 보여줄 유형 번호를 `|`로 구분해 적는다(예: `T01|T04`).
- `세부태그`: 유형의 세부 질문 선택지와 연결한다. `질문id.선택지id` 꼴이다(예: `D02.wage_required`). 많이 겹칠수록 앞에 나온다. `match_tags`인 유형에서는 이 태그가 없으면 그 주제를 고른 사람에게 나오지 않으므로, 새 행을 넣을 때 꼭 붙인다(`test_every_detail_topic_has_a_place_today`가 빈 주제를 알려 준다).
- `대상성별`(`male`/`female`), `최소나이`·`최대나이`(만 나이 숫자), `대상재직상태`(`employed`/`self_employed`/`not_working`, 여럿이면 `|`): 공식 안내에 분명히 적힌 대상 조건만 적는다. 답한 성별·나이·일 여부가 여기에 안 맞으면 그 사람에게는 이 행이 나오지 않는다. 확실하지 않으면 비워 두고(=누구에게나 보여 줌) `대상` 칸에 글로 적는다. 11/22 기준 `대상재직상태`는 모든 행이 비어 있다.
- `종류`: `상시서비스` / `기간프로그램` / `목록`. `목록`은 '목록에서 직접 찾아보기'에만 나오고 AI 후보에는 넣지 않는다. 목록 행은 둘러보기용이라, 새 회원 모집이나 접수 여부가 확인되지 않아도 `매칭가능`을 `Y`로 둘 수 있다(11/22 팀 결정: `L06_PIUM_DIRECTORY`, `L15`, `L16`). 이때 `확인필요`에 무엇을 직접 확인해야 하는지 적는다.
- `범위`: `안산` / `전국`. 전국 전화·온라인 창구는 안산 기관 뒤에 나온다.
- `첫상담`: `Y`면 유형과 상관없이 안내하는 일반 창구다. 대표 유형이 없는 사람과 맞는 곳을 찾지 못한 사람에게 보여준다.
- `한줄설명`, `상세설명`, `키워드`, `대상`: AI가 사용자가 적은 글과 비교하는 내용이다. 구체적으로 적을수록 잘 맞는다.
- `첫연락문장`: 카드의 "이렇게 물어보세요"에 그대로 나온다.

## 익명 기록

기본은 남기지 않는다(`settings.yaml`의 `save_log: false`). `true`로 바꾸면 `app/logs/`에 쌓이고(git에 올라가지 않음), 시작 화면 문구가 "저장해요"로 바뀐다. 참여자에게도 저장한다는 사실을 알려야 한다.

- `responses.csv`: 한 번 진행에 한 행(결과 화면에 처음 왔을 때).
  - 무작위 번호, 날짜와 시간(시 단위)
  - `state` 판정 상태, `primary` 대표 유형, `secondary` 함께 살펴볼 유형, `candidates` 최고점 유형들
  - `scores` 유형 점수(`T01=10|T02=4`), `answers` 척도 답(`Q01=5|Q02=3`)
  - `barriers` 걸림돌, `program_ids` 화면에 나온 프로그램
  - 성별·태어난 해·일 여부는 남기지 않는다(11/22). 맞는 곳을 고르는 데만 쓴다
- `events.csv`: 그 뒤의 행동. 먼저 볼 유형 고르기(`priority`), 세부 질문 답(`detail`. 마음·건강처럼 `log_answer: false`인 질문은 답했다는 사실만 남기고 고른 선택지는 비운다), 더 보기(`more`), 다른 유형 열기(`browse`), 돌아가서 답을 바꿈(`answers_changed`), AI 추가 추천(`ai`: 결과 상태와 고른 프로그램 id)
- `errors.log`: AI 호출이나 기록이 실패했을 때 오류의 종류만. 이 파일은 `save_log`와 상관없이 남는다.
- 이름, 연락처, 직접 적은 글은 어디에도 저장하지 않는다. 기본정보(성별·태어난 해·일 여부)도 저장하지 않는다. 글은 주민번호·전화번호·이메일 형태를 지운 뒤 AI에게만 보낸다.
- 기록 열이 바뀌면 예전 `responses.csv`는 이름에 `_이전형식_`을 붙여 보관하고 새 파일로 시작한다.
- 참여자가 적으면 시간과 답의 조합만으로도 누구인지 짐작될 수 있다. 기록 파일은 팀 밖으로 내보내지 않고, 발표에는 합계만 쓴다.

## 코드를 고쳤을 때

`app/` 안의 파이썬 파일을 고치면 앱을 껐다가 다시 켠다. 데이터 파일은 새로고침만 하면 된다.

구조: 내용은 데이터 파일, 판단은 `core/`(화면과 무관한 함수), 화면은 `main.py`와 `ui/`가 맡는다.

| 파일 | 하는 일 |
|---|---|
| `core/loader.py` | 데이터 파일을 읽고 형식을 검사 |
| `core/selection.py` | 문항 순서, 유형별 문항 연결표, 선택지, 걸림돌 안내 |
| `core/scoring.py` | 척도 답을 유형 점수로 바꾸고 먼저 살펴볼 유형을 정함 |
| `core/candidates.py` | 정보표에서 유형별 후보를 거르고 순서를 정함. 거르기는 여기서만 한다 |
| `core/llm_matcher.py` | AI 지시문 조립, 호출, 답 검증 |
| `core/privacy.py` | 글에서 전화번호·이메일 형태를 지움 |
| `core/logger.py` | 익명 기록. 한 행에 무엇을 남길지도 여기서 정한다 |
| `core/clock.py` | 한국 시각 |
