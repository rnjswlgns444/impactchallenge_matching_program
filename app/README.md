# 나에게 맞는 안산 프로그램 찾기

질문 3개 → 고른 문장이 그대로 유형(여러 개 가능) → 유형별로 지금 문의할 수 있는 곳 안내(물어볼 문장 · 전화 · 신청 방법).
결과 화면에서 원하는 점을 직접 적으면, 그 사람에게만 AI가 정보표 안에서 관련 있는 곳을 골라 이유와 함께 덧붙인다.

- 유형은 AI가 정하지 않는다. 사용자가 고른 문장이 유형이다.
- 기본 결과는 AI 없이 프로그램 정보표에서 걸러서 만든다. AI가 실패해도 기본 결과는 그대로 나온다.
- 프로그램 정보표는 공식 출처에서 확인한 내용이다. 행마다 `확인날짜`와 `출처URL`이 있다.

## 실행

프로젝트 루트(이 폴더의 위 폴더)에서 실행한다.

```
.venv\Scripts\python -m pip install -r app\requirements.txt
.venv\Scripts\python -m streamlit run app\main.py
```

- PC: http://localhost:8501
- 휴대폰: PC와 같은 와이파이에 연결한 뒤, 실행 창에 나오는 Network URL로 접속한다.
- 테스트: `.venv\Scripts\python -m pytest app\tests` (실제 AI는 부르지 않는다)

## AI 추가 추천 켜기

지금은 구글 Gemini API의 무료 구간을 쓴다(`data/settings.yaml`의 `llm.provider: gemini`).
키는 https://aistudio.google.com/apikey 에서 발급받는다.

- PC에서 실행할 때: `.streamlit/secrets.toml` 파일을 만들고 아래 한 줄을 넣는다. 이 파일은 git에 올라가지 않는다.
- 배포된 앱: Streamlit Cloud의 앱 Settings → Secrets에 같은 한 줄을 넣는다.

```
GEMINI_API_KEY = "여기에 키"
```

키가 없거나 AI가 답하지 못하면 "지금은 맞춤 찾기가 되지 않아요" 안내만 나오고, 위쪽의 기본 결과는 그대로다.
`settings.yaml`의 `show_error_kind: true`는 실패 원인의 종류를 화면에 작게 보여주는 점검용 설정이다. 실험 전에 `false`로 바꾼다.

무료 구간에서는 보낸 내용을 구글이 서비스 개선에 쓸 수 있다. 그래서 글 상자 아래 안내에 "AI 서비스에 보낸다"고 적었고, 전화번호·이메일 형태는 보내기 전에 지운다(이름은 지우지 못한다).
Claude로 바꾸려면 `llm.provider: anthropic`, `llm.model: claude-opus-5-5`로 고치고 `ANTHROPIC_API_KEY`를 넣는다.

### AI가 하는 일과 하지 않는 일

1. 사용자가 글을 적고 "적은 내용으로 찾아보기"를 누를 때만 한 번 부른다. 적지 않으면 부르지 않는다.
2. AI에게는 코드가 걸러 준 후보만 보낸다. 고른 유형들의 '문의할 곳'이고, 유형을 정하지 않았으면 지금 보여줘도 되는 곳 전체다.
3. AI가 고른 id는 후보와 다시 대조한다. 후보에 없는 것(지어낸 것, 끝난 것)은 화면에 나오지 않는다.
4. 결과 상태는 세 가지다. `ok` 글에 맞는 곳을 찾음 / `partial` 일부나 전부를 찾지 못함(일반 창구로 잇는다) / `fail` AI 호출 실패.

### 정답표로 확인하기

지시문, 모델, 프로그램 정보표를 바꾸면 가상 사례(`tests/matching_cases.yaml`)로 다시 확인한다.

```
.venv\Scripts\python app\tests\eval_matching.py --check     # AI를 부르지 않고 정답표가 정보표와 맞는지만 확인
.venv\Scripts\python app\tests\eval_matching.py             # 실제 AI로 정확도와 시간 측정 (사례 사이 12초 쉼)
```

## 내용을 고치는 법 (코드 수정 없음)

파일을 저장하고 브라우저를 새로고침하면 반영된다. 형식이 틀리면 화면에 어느 파일 어디가 틀렸는지 나온다.
각 파일 맨 위 주석에 칸의 뜻이 적혀 있다.

| 고치고 싶은 것 | 파일 |
|---|---|
| 질문과 선택지, 걸림돌별 안내 | `data/questions.yaml` |
| 유형 이름·문장, 유형별 세부 질문 | `data/types.yaml` |
| 프로그램·센터 정보 | `data/programs.csv` (엑셀로 열고 'CSV UTF-8'로 저장) |
| 화면 문구, 유형마다 먼저 보여줄 곳의 수, 기록 켜기, AI 모델 | `data/settings.yaml` |
| AI에게 주는 지시문 | `prompts/matching.md` (`{type_name}` 같은 자리표시자 6개는 지우지 않는다) |

문항 id(`Q_NEEDS`, `Q_BARRIER`, `Q_START`, `Q_PRIORITY`, `Q_FREE`)와 유형 id(`T01`~`T12`)는 코드와 정보표가 쓰므로 바꾸지 않는다.

### 프로그램 정보표(programs.csv)에서 꼭 알아둘 열

- `매칭가능`이 `Y`이고, `55~64세참여`가 `불가`가 아니고, `표시종료일`이 지나지 않은 행만 화면과 AI에 나간다. 끝난 프로그램은 지우지 말고 `N`으로 둔다. `Y`면 `출처URL`이 있어야 한다.
- `유형태그`: 이 프로그램을 보여줄 유형 번호를 `|`로 구분해 적는다(예: `T01|T04`).
- `세부태그`: 유형의 세부 질문 선택지와 연결한다. `질문id.선택지id` 꼴이다(예: `D02.wage_required`). 많이 겹칠수록 앞에 나온다.
- `종류`: `상시서비스` / `기간프로그램` / `목록`. `목록`은 '목록에서 직접 찾아보기'에만 나오고 AI 후보에는 넣지 않는다.
- `범위`: `안산` / `전국`. 전국 전화·온라인 창구는 안산 기관 뒤에 나온다.
- `첫상담`: `Y`면 유형과 상관없이 안내하는 일반 창구다. 유형을 정하지 않은 사람과 맞는 곳을 찾지 못한 사람에게 보여준다.
- `한줄설명`, `상세설명`, `키워드`, `대상`: AI가 사용자가 적은 글과 비교하는 내용이다. 구체적으로 적을수록 잘 맞는다.
- `첫연락문장`: 카드의 "이렇게 물어보세요"에 그대로 나온다.

## 익명 기록

기본은 남기지 않는다(`settings.yaml`의 `save_log: false`). `true`로 바꾸면 `app/logs/`에 쌓이고(git에 올라가지 않음), 시작 화면 문구가 "저장해요"로 바뀐다. 참여자에게도 저장한다는 사실을 알려야 한다.

- `responses.csv`: 한 번 진행에 한 행. 무작위 번호, 날짜와 시간(시 단위), 고른 유형, 걸림돌, 시작 방식, 화면에 나온 프로그램
- `events.csv`: 그 뒤의 행동. 먼저 볼 유형(`priority`), 세부 질문 답(`detail`), 더 보기(`more`), 둘러보기(`browse`), AI 추가 추천(`ai`: 결과 상태와 고른 프로그램 id)
- `errors.log`: AI 호출이나 기록이 실패했을 때 오류의 종류만. 이 파일은 `save_log`와 상관없이 남는다.
- 이름, 연락처, 직접 적은 글은 어디에도 저장하지 않는다. 글은 전화번호·이메일 형태를 지운 뒤 AI에게만 보낸다.

## 코드를 고쳤을 때

`app/` 안의 파이썬 파일을 고치면 앱을 껐다가 다시 켠다. 데이터 파일은 새로고침만 하면 된다.

구조: 내용은 데이터 파일, 판단은 `core/`(화면과 무관한 함수), 화면은 `main.py`와 `ui/`가 맡는다.

| 파일 | 하는 일 |
|---|---|
| `core/loader.py` | 데이터 파일을 읽고 형식을 검사 |
| `core/selection.py` | 답을 유형과 안내로 바꿈 |
| `core/candidates.py` | 정보표에서 유형별 후보를 거르고 순서를 정함. 거르기는 여기서만 한다 |
| `core/llm_matcher.py` | AI 지시문 조립, 호출, 답 검증 |
| `core/privacy.py` | 글에서 전화번호·이메일 형태를 지움 |
| `core/logger.py` | 익명 기록 |
